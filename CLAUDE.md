# Сервис — учёт ремонта оборудования

Кроссплатформенное настольное приложение: список оборудования в ремонте, карточка заявки
с историей статусов и вложениями, компактный виджет поверх других окон, экспорт в Excel и PDF.

## Команды

```bash
npm run dev          # дев-сервер на http://localhost:5180 (главное окно)
                     # виджет отдельно: http://localhost:5180/widget.html
npm run build        # tsc --noEmit + сборка в dist/
npm run tauri dev    # настольное приложение с горячей перезагрузкой
npm run tauri build  # установщик для текущей системы
```

Проверять изменения нужно и сборкой (`npm run build`), и глазами в браузере: значительная
часть логики — это раскладка и печать, их типизация не ловит.

## Архитектура

Фронтенд — React 19 + TypeScript + Vite, стили — обычный CSS с переменными, без UI-библиотек.
Две точки входа Vite: `index.html` (главное окно) и `widget.html` (компактный виджет).

Доступ к данным изолирован интерфейсом `RepairRepo` (`src/repairs/repo.ts`). `getRepo()`
возвращает `repo.sqlite`, когда приложение запущено внутри Tauri, и `repo.mock` в браузере.
Благодаря этому весь интерфейс работает в обычном браузере на демо-данных — там и ведётся
разработка дизайна.

- `src/repairs/store.ts` — Zustand-стор: список, фильтры, выбор, вложения, экспорт
- `src/repairs/repo.mock.ts` — браузерная реализация: метаданные в localStorage,
  содержимое файлов в IndexedDB (`src/lib/blobstore.ts`), иначе видео не помещается
- `src/repairs/repo.sqlite.ts` — настольная реализация: SQLite через `tauri-plugin-sql`,
  файлы в подпапке `files` каталога данных, наружу отдаются asset-ссылки и путь на диске
- `src/repairs/FileManager.tsx` — файловый менеджер карточки: разделы, поиск, сортировка,
  список и плитка, множественный выбор, панель просмотра выделенного файла
- `src/repairs/FileView.tsx` — показ одного файла: фото, видео и PDF отдаются движку,
  остальное разбирается на месте
- `src/lib/preview.ts` — разбор форматов для показа внутри: таблицы через SheetJS,
  Word через mammoth, ODT и архивы распаковкой, текст с подбором кодировки
- `src/lib/files.ts` — действия снаружи приложения через `tauri-plugin-opener`:
  открыть системной программой, показать в папке, сохранить копию
- `src/repairs/demo.ts` — демонстрационный набор, общий для обеих реализаций
- `src-tauri/src/lib.rs` — окна, трей, миграции SQL, команды `show_main_window`,
  `toggle_widget`, `notify_changed`; после каждой мутации окна синхронизируются
  событием `repairs:changed` (подписка — `src/lib/sync.ts`)
- `src/theme/tokens.css` — все переменные оформления; тема, гамма, шрифт, плотность,
  скругление применяются через `ThemeProvider` на `:root`
- `src/settings/store.ts` — настройки (persist в localStorage)
- `src/export/` — выгрузка: `excel.ts` (SheetJS, три листа) и `Report.tsx`
  (постраничный отчёт A4 с собственной пагинацией по замеренным высотам блоков)

## Соглашения

- Интерфейс на русском; тексты в коде — тоже на русском, без англицизмов вроде «экспортнуть»
- Цвета только через переменные из `tokens.css` — жёсткие hex ломают светлую тему.
  Исключение: `src/export/report.css` и `Report.tsx`, где лист всегда белый
- Ошибки показываются рядом с действием, а не через `alert`
- Вложения не отбраковываются по расширению: плеер пробует открыть файл, решение
  принимает движок, при отказе показывается `MediaFallback` с выходом наружу
- Файл сначала пробуем показать внутри приложения и только потом отдаём системе:
  `previewKindOf` решает, чем показывать, наружу уходит лишь то, для чего просмотра нет
- Разметка из чужих документов проходит через `sanitizeHtml`: документ приносит
  пользователь, поэтому в карточку попадает только безопасный набор тегов

## Решения, которые не видны из кода

- Форм-фактор выбран пользователем: компактный виджет поверх других окон **и** полное окно
- Полей «срок» и «приоритет» сознательно нет — вместо просрочки считается «долго в ремонте»
  по порогу в днях из настроек
- Номер заявки редактируется вручную и проверяется на уникальность; пустое поле означает
  автонумерацию, ручной числовой номер сдвигает счётчик
- Содержимое вложений в браузере лежит в IndexedDB, а не в localStorage: видео с телефона
  не помещается в пятимегабайтный лимит
- Видео не отбраковывается по расширению — плеер пробует открыть любой файл, решение
  принимает движок; источник записей это iPhone (MOV, HEVC) и Android
- Штамп на фото и видео рисуется поверх при просмотре, файл не изменяется
- Отчёт PDF раскладывается по листам A4 самостоятельно, по замеренным высотам блоков:
  печать средствами браузера разрывала таблицу и карточки в произвольных местах

## Сборка и распространение

Установщики собирает GitHub Actions (`.github/workflows/build.yml`) — кнопкой Run workflow
или тегом `v*`. Репозиторий: https://github.com/atabaevkirill-dev/services

Сборки не подписаны: на macOS нужен правый клик → «Открыть» или снятие карантина,
на Windows — «Подробнее» → «Выполнить в любом случае» в окне SmartScreen. Подпись
потребует Apple Developer Program и сертификата Windows, в CI это добавляется секретами.

## Незавершённое

- `src/lib/ocr.ts` — автозаполнение заявки из скана акта (PDF), пока `NotImplementedError`
- `src/lib/transcode.ts` — приведение видео к mp4 через ffmpeg в десктопной сборке
- Настольная сборка собирается и запускается на Windows, SQLite и файлы на диске работают;
  трей, виджет и системные действия с файлами вживую ещё не прощёлкивались
- Старый `.doc` и архивы `.rar`/`.7z` внутри не показываются — только системной программой
- Команда `toggle_widget` есть в Rust, но из интерфейса не вызывается: виджет
  открывается только из меню трея
- Переключатель «Поверх других окон» в настройках ни на что не влияет —
  `setAlwaysOnTop` не вызывается
- Настройки оформления по-прежнему в `localStorage`; в Tauri он переживает перезапуск,
  но при переносе на другую машину не переезжает
